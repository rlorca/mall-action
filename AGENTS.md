# AGENTS.md: MALL ACTION (branch `sonnet-5-5-fable-5-1`)

An 8-bit spy caper in an 80s shopping mall, built from the shared brief (`one-shot-prompt.md` on `main`).
TypeScript + Vite + Vitest. No runtime dependencies, no external assets: every sprite, tile, glyph, song and
sound effect is generated from source code. **Read this file before touching anything.**

## Architecture: layers and rules that must hold

```
src/engine/     pure, DOM-free building blocks (rng, loop, input mapping, palette, framebuffer, sprite pipeline, fonts)
src/content/    DATA only: stores, layout geometry, power-ups, ALL copy (jokes) in copy.ts
src/art/        sprite definitions (char grids -> registry) + storefront drawing. Pure.
src/game/       THE RULES. Pure, deterministic, testable without a browser.
  run.ts          whole-game state: score, lives, continues, loop, power-ups, inventory, per-game flags
  difficulty.ts   per-loop scaling
  levelstate.ts   per-level store contents (generated by store/levelgen.ts)
  mall/           side-scroller world (physics, elevators, escalators, spies, lights, NPCs)
  store/          top-down rooms
  screens/        title, map data, level clear, continue, game over (state machines)
  game.ts         the scene machine: splash -> title -> level (mall <-> store, map, pause) -> clear/continue/over
src/render/     draws game state into the Framebuffer (and the WebGL/CRT presenter). No rules.
src/audio/      pure song data + sequencer (tested) and the Web Audio NES synth
src/flickersoft/  self-contained, reusable studio splash module (has its own README)
src/main.ts     browser bootstrap only (canvas, WebGL, audio unlock, input events, rAF, debug hooks)
```

### Rules that must hold (tests enforce several)

1. **Rules never touch the DOM, `Math.random`, `Date`, `performance`, or `requestAnimationFrame`.** `src/determinism.test.ts`
   greps `engine/ game/ content/ art/ flickersoft/` for them. All randomness goes through `Rng` (`src/engine/rng.ts`);
   give each subsystem its own `rng.fork('label')` so adding randomness in one place never shifts another.
2. **Frames are the only unit of time.** The sim runs at a fixed 60 Hz. Durations are written as frame counts (`2 * 60`).
3. **One entry point for advancing the game:** `game.step(pad)`. The rAF loop and the `?debug=1` stepper both call it.
4. **Rules emit, renderers react.** Rules put sound requests into `run.sfx(id)` (drained by the Game) and expose the
   music they want via state; renderers/audio only read state. Rendering never mutates rules state.
5. **Framebuffer + palette indices.** All drawing goes to `Framebuffer` (256x240 NES palette indices, see
   `engine/framebuffer.ts`). Use the named colours in `engine/palette.ts` (`C.RED`, ...). Never use RGB.
6. **Sprites: max 3 colours + transparent**, enforced by `parseSprite`. Characters are drawn facing RIGHT and flipped
   for left. All copy lives in `content/copy.ts`; `content/content.test.ts` checks every line fits.
7. **Everything is positioned in whole pixels at draw time** (round when drawing; sim may use fractions).
8. **No external assets.** If you need a picture, define a char grid; if you need a sound, describe it as data.

### Coordinates and geometry (see `src/content/layout.ts`; it is the source of truth)

* Mall is 768 px wide; y grows DOWN. Floors are 48 px apart: index 0 = R (roof), 1 = 4F, 2 = 3F, 3 = 2F, 4 = 1F, 5 = P.
  `floorY(f)` is the walking surface (the agent's feet y). Slab is 8 px thick below the surface; the ceiling above a
  floor is `floorY(f) - 40`.
* Screen: 256x240; the top 16 px is the HUD strip; the play view is 256x224 starting at y = 16.
* Shafts A (R..2F, manual), B (4F..P, manual), C (R..1F, automatic) are 24 px wide; the car is 24x32 (its floor is the
  surface the agent stands on; its roof is 32 px higher). Escalators E1 (3F<->4F) and E2 (1F<->2F).
* Store doors: storefront left edge `x`, door trigger `x + 32 .. x + 48`.
* Top-down rooms: 16 x 11 tiles of 16 px; the room is drawn at screen y = 16; door at the bottom centre (columns 7-8).

### The sprite contract

`src/art/manifest.ts` lists every REQUIRED sprite (name, w x h, min frames, owner). Art modules call
`defineSprites([...])` (`src/art/registry.ts`); renderers call `getSprite(name)`. `src/art/manifest.test.ts` fails if
anything is missing, wrong-sized, over 3 colours or has an empty frame. Extra sprites with other names are fine.
Sprite source format (`SpriteDef`): `{ name, w, h, pal: { K: C.BLACK, R: C.RED, ... }, rows: [...] }` or
`frames: [[...], [...]]`; `.`/space = transparent; every row exactly `w` chars.

## Module contracts (who writes what, and the interfaces between them)

### Pad and input
`Pad = { held, pressed, released }` bit masks of `Btn.*` (`engine/pad.ts`). `pressed` = rising edge this step.

### Run (`src/game/run.ts`)
Persistent across scenes. Key API: `run.addScore(n)`, `run.sfx(id)`, `run.givePower(id)`, `run.tickPowers()` (call once
per step in mall AND stores), `run.absorbHit()`, `run.fireProfile()`, `run.walkFactor()`, `run.jumpFactor()`,
`run.searchFrames()`, `run.loseLife()`, `run.useContinue()`, `run.addJoke(name)`, `run.level` (the `LevelState`),
`run.seenStores` / `run.easterEggDone` (per-game "first time" flags), `run.blackFriday`, `run.rng`.

### Store world (`src/game/store/`)
```ts
class StoreWorld {
  constructor(run: Run, storeId: StoreId, rng: Rng)       // uses run.level.stores[storeId]
  step(pad: Pad): void                                      // one 60 Hz frame
  readonly exited: boolean                                  // agent walked out the door -> mall fades back in at the door
  readonly died: boolean                                    // agent was killed -> Game calls run.loseLife() and returns to the mall at that door
  music(): MusicId                                          // the store's own song, or 'booth' while on the listening booth
  // plus public read-only render state: room, tiles, agent, guards, bullets, banner, bubbles, search progress, popups...
}
generateLevel(rng: Rng, loop: number, blackFriday: boolean): LevelState   // src/game/store/levelgen.ts
```
Rules: exactly one package per target store; power-up shops never trapped and hold only power-ups/nothing; Black Friday
makes every non-package fixture a power-up; searched fixtures stay open (state lives in `run.level`, not in the world).
Rendering of rooms lives in `src/render/storeView.ts`: `drawStore(fb, world, frame)`.

### Screens (`src/game/screens/` + `src/render/*View.ts`)
Each screen is a small state machine (`step(pad)`) plus a draw function. See each file's header. HUD:
`drawHud(fb, hud: HudData)` in `src/render/hud.ts`.

### Audio (`src/audio/`)
`AudioEngine` facade: `unlock()` (after first user input), `setMusic(id | null)`, `setDuck(boolean)` (pause = quieter),
`sfx(id)`, `setMuted(b)`, `isMuted()`. Song data and the sequencer are pure and unit-tested; only `synth.ts`/`audio.ts`
touch Web Audio. If audio cannot start the game must run fine.

## Verification checklist for any change

1. `npm run typecheck && npm test && npm run build`.
2. Rendering change? `npx tsx scripts/sheet.ts ...` or write a tiny script that draws to a `Framebuffer` and
   `writeFramebufferPng(...)` (from `scripts/png.ts`), then LOOK at the PNG.
3. Gameplay change? Add or extend a rules test (pure, no browser). Then play it in a real browser at
   `http://localhost:5173/?debug=1&seed=1` with the CRT on and check the console for errors.

## Mall rules cheat-sheet (the tricky bits, all covered by tests in `src/game/mall/`)

* **Shaft openings** (per car and floor): `here` (car level: walk in), `above` (grate: you can stand on it, a descending car crushes you
  unless it was called for you), `blocked` (car body passing the doorway: solid), `pit` (roof at/below the floor: you fall; roof within
  one floor = safe, further = fatal). Spies never enter pits; the automatic car never leaves while someone is inside.
* **Shaft walls**: you can only cross a shaft wall at a floor's "door window" (feet within 30 px above that floor's surface). That is
  what lets you jump out of a car roof, and what stops you walking through a moving car.
* **Driving**: Up/Down while riding moves the car 1 px/frame (it passes floors without stopping); releasing between floors glides to the
  next floor in that direction and stops exactly level with ONE `ding` (the ding is emitted on the moving->stopped transition only).
* **Calling**: Up/Down beside or in an empty opening, or standing still there for 30 frames. A called car carries `protectFloor` so it
  picks the caller up instead of crushing him.
* **Death flow**: `hurtPlayer(cause, armourable)` -> dying animation (70 frames) -> `run.loseLife()` -> respawn at the last safe spot with
  120 frames of blinking invulnerability, or `outcome = 'continue' | 'gameover'` for the Game.

## Gotchas

* **Vitest/TypeScript versions**: this repo uses TypeScript 7, Vite 8, Vitest 5. `vite.config.ts` imports `defineConfig` from
  `vitest/config` so the `test` block typechecks.
* **Bot-style tests must behave like a player**: a scripted agent that walks straight over an open shaft falls in. `route.test.ts` waits
  beside the opening and jump-kicks over pits.
* **Boarding presses also drive**: the frame you press Down to board a car, the car already starts moving 1 px; tests should drive until
  the car reaches a floor rather than assuming it starts at a floor.
* **`player.cause` resets on respawn**: tests record causes through the rig (`rig.causes`) instead of reading the player after the fact.
* **CRT shader**: curvature is zoom-compensated so the corners land exactly on the screen corners; do not increase `k` without checking
  that the HUD text (top rows) is not clipped at the centre of the top edge.
* **Integer scale is computed in device pixels** (`engine/scale.ts`): on Retina a 1280x800 window gives the same crisp scale as 2560x1600.
